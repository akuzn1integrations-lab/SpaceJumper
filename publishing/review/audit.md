# SpaceJumper — пошаговая проверка и публикация в Яндекс Играх

**Дата актуализации:** 21 ноября 2026 г.  
**Репозиторий:** https://github.com/akuzn1integrations-lab/SpaceJumper  
**Исходный код:** ветка main, версия 1.2.0.  
**Цель:** получить проверенный ZIP, заполненную карточку RU/EN и отправить игру на модерацию без потери сохранений и работоспособности.

> **Статус:** наличие SDK и нужных функций подтверждено просмотром кода. Автотесты, тестирование в браузерах, проверка реальной Консоли и модерация **не проводились** в рамках этого аудита. Ни один пункт ниже нельзя считать пройденным до фактической проверки. Требования платформы меняются: перед отправкой обязательно сверяйтесь с официальной документацией и подсказками в Консоли.

## 2. Проверить синтаксис и автотесты

Из корня репозитория:

~~~powershell
node --check engine.js
node --check music.js
node --check i18n.js
node --check platform.js
node --check app.js
node --test tests/*.test.js
~~~

В Windows PowerShell маска tests/*.test.js может не раскрыться в зависимости от версии Node/оболочки. Надёжная альтернатива:

~~~powershell
Get-ChildItem tests -Filter *.test.js | ForEach-Object { node --test $_.FullName }
~~~

В macOS/Linux используйте:

~~~bash
node --check engine.js && node --check music.js && node --check i18n.js && node --check platform.js && node --check app.js
node --test tests/*.test.js
~~~

**Критерий:** все проверки завершаются с кодом 0; нет failed/not ok и SyntaxError. При ошибке скопируйте полный текст, имя теста и версию Node. Не отправляйте игру на модерацию при падающих тестах. Автотесты не заменяют ручной плейтест.

## 3. Запустить игру локально

~~~powershell
python -m http.server 8080
~~~

На macOS/Linux:

~~~bash
python3 -m http.server 8080
~~~

Откройте http://localhost:8080/ в браузере. Остановить сервер — Ctrl+C.

**Важно:** при локальном запуске без SDK игра должна работать в резервном режиме; ошибки загрузки /sdk.js в локальной среде ожидаемы. Для проверки SDK, рекламы, облака и событий используйте среду Консоли Яндекс Игр, а не localhost. Не запускайте index.html напрямую через file://.

Проверить вручную:
1. Меню → обучение → обычный забег; клавиши A/D, стрелки, Space, Esc.
2. Прыжки сквозь платформы снизу, посадка сверху, подбор бонусов, урон, смерть, повтор.
3. Уровни 6/10/16: рост обычных лазеров и появление мин (для ускорения допустим отдельный локальный тестовый сценарий, **не включаемый в ZIP**).
4. Пауза при переключении вкладки; музыка должна останавливаться. После возвращения не должно быть внезапного проигрывания звука без действия игрока.
5. Настройки громкости, уменьшения анимаций и переназначения клавиш.
6. После обновления страницы локальный рекорд и настройки сохраняются, если localStorage доступен.

**Критерий:** нет зависаний, непреднамеренного старта, потери управления или необработанных ошибок в DevTools → Console. Для открытия DevTools обычно F12 / Ctrl+Shift+I (Windows/Linux), Cmd+Option+I (macOS).

## 4. Собрать и проверить архив для Консоли

**Windows:** из корня проекта:

~~~powershell
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
~~~

Ожидаемый файл: build/spacejumper.zip. Скрипт копирует только необходимые файлы игры и папку assets, если она есть. Папка publishing **не входит** в игровой ZIP.

**macOS/Linux — эквивалентная сборка без PowerShell:**

~~~bash
python3 - <<'PY'
from pathlib import Path
from zipfile import ZipFile, ZIP_DEFLATED
root = Path.cwd()
required = ['index.html','style.css','engine.js','music.js','i18n.js','platform.js','app.js']
for name in required:
    if not (root/name).is_file():
        raise SystemExit(f'Missing required file: {name}')
out = root/'build'/'spacejumper.zip'
out.parent.mkdir(parents=True, exist_ok=True)
with ZipFile(out,'w',ZIP_DEFLATED) as archive:
    for name in required:
        archive.write(root/name,name)
    assets = root/'assets'
    if assets.exists():
        for file in assets.rglob('*'):
            if file.is_file():
                archive.write(file,file.relative_to(root).as_posix())
print(out)
PY
~~~

**Проверка архива (Windows PowerShell):**

~~~powershell
python -c "from zipfile import ZipFile; z=ZipFile('build/spacejumper.zip'); n=z.namelist(); print('\n'.join(n)); assert 'index.html' in n; assert all(not x.startswith('/') and '..' not in x.split('/') for x in n); print('ZIP OK')"
Get-Item build/spacejumper.zip | Select-Object Name,Length
~~~

**macOS/Linux:**

~~~bash
python3 -c "from zipfile import ZipFile; z=ZipFile('build/spacejumper.zip'); n=z.namelist(); print('\n'.join(n)); assert 'index.html' in n; assert all(not x.startswith('/') and '..' not in x.split('/') for x in n); print('ZIP OK')"
ls -lh build/spacejumper.zip
~~~

**Критерий:** index.html расположен прямо в корне архива, а не в папке spacejumper/; все JS/CSS доступны; нет tests/, docs/, publishing/, .git/ и локальных SDK-заглушек. Сверьте ограничения размера архива и имён файлов с актуальной Консолью.

## 5. Создать черновик в Консоли Яндекс Игр

1. Откройте https://games.yandex.ru/console и войдите в аккаунт разработчика.
2. Завершите необходимые шаги регистрации и оформления отношений с платформой, если Консоль их запрашивает.
3. Создайте новую HTML5-игру / черновик.
4. Укажите **SpaceJumper**. Выберите категории, соответствующие аркаде и платформеру, и только фактически проверенные устройства (Desktop/Mobile; TV не выбирайте без отдельной проверки).
5. Загрузите build/spacejumper.zip в предусмотренное поле сборки.
6. Включите/отметьте используемые возможности: SDK, сохранение прогресса, лидерборд, рекламу — в соответствии с полями текущей Консоли.
7. Сохраните черновик. **Не отправляйте на модерацию до выполнения остальных шагов.**

Интерфейс и названия полей могут отличаться; ориентируйтесь на фактические подсказки Консоли. Сохраните ID черновика и дату загрузки архива в собственных заметках (не публикуйте секретные данные в Git).

**Критерий:** сборка принята Консолью, доступен тестовый запуск, нет ошибок распаковки.

## 6. Проверить SDK в тестовой среде Яндекса

Откройте тестовый запуск игры из черновика в Консоли и, если доступна, debug-панель SDK (ищите «Debug», «Отладка», «Тестирование» в документации и Консоли).

В DevTools → Console / Network проверьте:
1. /sdk.js загружается без ошибки, YaGames.init() завершается успешно.
2. LoadingAPI.ready() вызывается после готовности игрового меню.
3. GameplayAPI.start() вызывается при старте/возобновлении активного забега, stop() — на паузе, экране результата, при рекламе и уходе со страницы.
4. События game_api_pause и game_api_resume не приводят к «двойному» запуску, пропуску паузы или продолжению игры в скрытой вкладке.
5. Не возникает uncaught exceptions, Promise rejection или бесконечного ожидания SDK.
6. При отсутствии SDK (локально) игра остаётся работоспособной без платформенных функций.

**Критерий:** события отражают реальное состояние игры; во время паузы и рекламы физика и музыка не продолжаются. Проверку нужно повторить на поддерживаемых браузерах и устройствах.

## 7. Проверить рекламу и звук

В исходном коде app.js после исправления полноэкранная реклама запрашивается **перед следующим стартом после двух завершённых обычных забегов**. Реклама вызывается только через SDK.

Тест:
1. Завершите обычный забег №1, нажмите «Ещё раз»: новая игра должна стартовать без межстраничной рекламы.
2. Завершите забег №2, нажмите «Ещё раз»: должен быть запрос рекламы (фактический показ зависит от SDK, доступности инвентаря и тестового режима).
3. Проверьте закрытие рекламы, ошибку показа и отсутствие рекламного инвентаря. Во всех случаях пользователь должен иметь возможность продолжить.
4. Повторите сценарий, возвращаясь в меню и начиная забег оттуда: обходить рекламную точку через меню нельзя.
5. На время рекламы игра и звук должны быть остановлены; после возвращения не должно быть двух одновременно играющих музыкальных циклов.
6. Сверьте частоту, формат, допустимые моменты показа и необходимость иных рекламных форматов с текущими правилами платформы.

**Критерий:** реклама не появляется посреди активного прыжка, нет блокировки игры после ошибки SDK, сохранения не теряются. Важно: сам факт вызова showFullscreenAdv не гарантирует показ рекламы.

## 8. Проверить облачные сохранения и лидерборд

В Консоли создайте лидерборд с **техническим именем spacejumper_best** (точно как в app.js); настройте его параметры и видимость согласно возможностям Консоли.

Тестовый план:
1. Запустите игру без авторизации: игра доступна, рекорд сохраняется локально.
2. Сделайте рекорд, обновите страницу: рекорд не исчез.
3. Если доступен тестовый профиль SDK, проверьте запись best и settings через player.setData(), чтение через player.getData(), а также setStats().
4. Проверьте синхронизацию на другом устройстве / в другом браузере **с тем же аккаунтом**, если это поддерживается текущими настройками.
5. Проверьте вход **только после нажатия кнопки** для рейтинга; автоматический запрос авторизации при открытии игры недопустим.
6. После входа проверьте отправку результата через leaderboards.setScore('spacejumper_best', score).
7. Отключите сеть / запретите хранилище в тестовой среде: игра должна продолжить работать, даже если сохранение не удалось.

**Критерий:** рекорд не уменьшается при загрузке облака; настройки сохраняются; рейтинг принимает результат только при корректных правах; игра без авторизации работает. Ошибки SDK нужно фиксировать с шагами воспроизведения.

## 9. Проверить RU/EN и адаптивность

**Локализация:** используйте языковые настройки/debug-панель платформы для принудительного выбора ru и en; не полагайтесь только на язык ОС. Проверьте меню, обучение, HUD, настройки, паузу, причины смерти, экран результата, уведомления, авторизацию рейтинга. В обоих языках не должно быть обрезанных кнопок или смешанных строк. Файл словарей: i18n.js.

**Desktop:** Chrome/Яндекс Браузер и Firefox; проверьте размеры окна 1280×720, 1920×1080 и узкое окно, масштаб браузера 100% и 125%, ввод с клавиатуры, потерю фокуса, отсутствие скролла.

**Android/iOS:** портретная ориентация, сенсорные кнопки, safe-area (вырез/индикатор), экранная клавиатура в настройках, смена ориентации, сворачивание и возвращение, системное отключение звука, поведение после рекламы. Не выбирайте неподтверждённые платформы в Консоли.

**Критерий:** игровой процесс не выходит за экран, кнопки доступны, прокрутки страницы и наложений нет, управление и аудио корректны.

## 10. Подготовить карточку и графику

Тексты:
- Русский: ../texts/ru.md
- Английский: ../texts/en.md

Исходные промоиллюстрации:
- ../images/icon_512x512.svg
- ../images/cover_800x470.svg
- ../images/promo_1200x630.svg

**Важно:** эти SVG — иллюстрации, а **не** скриншоты игры. Их нельзя выдавать за реальный геймплей. Консоль может требовать PNG/JPEG, конкретные размеры, соотношения сторон, ограничения текста/логотипа и объёма файлов. Проверяйте поля непосредственно перед загрузкой. SVG в папке — редактируемые исходники, а не гарантия приемлемого формата для Консоли.

Экспорт SVG в PNG через Inkscape (если установлен):

~~~powershell
inkscape publishing/images/icon_512x512.svg --export-filename=publishing/images/icon_512x512.png
inkscape publishing/images/cover_800x470.svg --export-filename=publishing/images/cover_800x470.png
inkscape publishing/images/promo_1200x630.svg --export-filename=publishing/images/promo_1200x630.png
~~~

На macOS/Linux команды аналогичны, если inkscape добавлен в PATH. При изменении требуемого размера используйте параметры --export-width и --export-height либо настройте размер в редакторе, **не растягивая изображение с нарушением пропорций**.

**Настоящие скриншоты:**
1. Запустите реальную игру из Консоли в тестовом режиме.
2. Сделайте 3–5 кадров с разными моментами геймплея: прыжок, бонусы, шипы/лазеры, мины, результат (число и требования уточните в Консоли).
3. Снимайте изображение игры без DevTools, курсора и посторонних окон; не подменяйте скриншоты иллюстрациями.
4. Проверьте читаемость и отсутствие ошибок/тестовых сообщений.
5. Если нужен ролик, запишите короткий фрагмент настоящего геймплея через OBS или встроенную запись экрана; формат, длительность и ориентацию сверяйте с Консолью.

**Возрастной рейтинг:** предварительная оценка 6+ — **не окончательное решение**. Заполните анкету и установите категорию согласно правилам платформы и содержимому игры.

**Критерий:** обе локали карточки заполнены, нет несоответствия описания реальным механикам, все медиа принимаются Консолью и отвечают текущим ограничениям.

## 12. Если модерация вернула замечания

1. Сохраните точный текст замечания и пункт требований, приложите скриншот/видео воспроизведения.
2. Найдите причину в игре или карточке; исправьте **конкретную** проблему.
3. Повторите затронутые тесты из разделов 2–10.
4. Пересоберите ZIP; убедитесь, что в Консоль загружена новая версия.
5. Отправьте повторно с кратким описанием исправления. Не обещайте исправления, которых нет в загруженной сборке.

## 13. Частые ошибки и решения

| Симптом | Что проверить |
| --- | --- |
| node: command not found / не распознано | Установите Node.js LTS, откройте новый терминал, проверьте node --version |
| python: command not found | Windows: установите Python с PATH; macOS/Linux: используйте python3 |
| PowerShell запрещает запуск скрипта | Используйте указанную команду powershell -ExecutionPolicy Bypass -File scripts/build.ps1; не меняйте системную политику глобально |
| /sdk.js 404 на localhost | Нормально для локального режима; проверяйте SDK через Консоль |
| В ZIP нет index.html в корне | Соберите архив через scripts/build.ps1 или команду из раздела 4, не архивируйте родительскую папку |
| Нет рекламы при тесте | Проверьте вызов SDK, тестовый режим, доступность рекламного инвентаря; отсутствие фактического показа не всегда ошибка |
| Рейтинг не работает | Проверьте техническое имя spacejumper_best, авторизацию, права и доступность метода |
| На iPhone нет музыки | Проверьте пользовательское действие перед AudioContext, системные ограничения звука, паузу и возобновление |
| Текст на английском обрезается | Проверьте все экраны в английской локали и размеры кнопок/оверлеев |
| Консоль отклоняет изображение | Сверьте формат, пиксельные размеры, пропорции и допустимый размер файла; SVG экспортируйте в PNG/JPEG |
