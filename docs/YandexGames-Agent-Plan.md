# План доработки SpaceJumper для публикации на Яндекс Играх

Пошаговая инструкция для агента-разработчика. Документ описывает, что менять, в каком порядке, как проверять каждый этап и когда можно считать работу завершённой.

Основание: [YandexGames-Publishing.md](YandexGames-Publishing.md) и актуальные требования Яндекс Игр на ноябрь 2026 года.

---

## 0. Как пользоваться планом

1. Выполняйте этапы строго по порядку. Следующий этап начинайте только после проверки предыдущего.
2. После каждого этапа запускайте команды из блока «Проверка».
3. Не меняйте физику, генерацию, начисление очков, тайминги и правила игры. Задача — интеграция с платформой, локализация, сохранения, реклама и компоновка.
4. Не добавляйте npm-зависимости, сборщики и внешние ресурсы.
5. Не коммитьте изменения без отдельной команды пользователя.
6. Если этап затрагивает `engine.js`, обязательно перезапускайте все тесты: детерминированность и достижимость платформ не должны сломаться.

### 0.1. Исходная проверка

Из корня проекта:

```powershell
git status --short
node --check engine.js
node --check app.js
node --check music.js
node --test tests/*.test.js
```

Ожидаемый baseline: 19 тестов проходят. Зафиксируйте результат, чтобы отличать новые ошибки от существующих.

### 0.2. Границы изменений

Разрешено менять:

- `index.html`;
- `style.css`;
- `app.js`;
- `engine.js` — только коды причин смерти и структуру событий, без изменения правил;
- новые файлы `platform.js`, `i18n.js`;
- тесты;
- `README.md`;
- build-скрипт, если он нужен.

Запрещено:

- менять константы прыжка, гравитации, скорости, шага симуляции;
- менять алгоритм генерации платформ и проверку достижимости;
- менять правила начисления очков и бонусов;
- добавлять внешние URL, шрифты, CDN, сторонние SDK и аналитику;
- добавлять покупки и кастомные рекламные блоки;
- добавлять интерактивный ИИ;
- добавлять надписи «demo», «beta», «в разработке»;
- включать в архив `tests`, `docs`, `.git`, локальную заглушку SDK.

## 1. Цель и определение готовности

### 1.1. Техническая готовность

Работа считается завершённой, когда:

- [ ] SDK подключён через `/sdk.js`, `YaGames.init()` не даёт ошибок.
- [ ] `LoadingAPI.ready()` вызывается после появления меню.
- [ ] `GameplayAPI.start()` и `stop()` вызываются в правильных точках.
- [ ] Обрабатываются `game_api_pause` и `game_api_resume`.
- [ ] Звук останавливается при потере фокуса, паузе и рекламе.
- [ ] Рекорд и настройки сохраняются локально и в облаке.
- [ ] Работает автоопределение языка, есть русский и английский.
- [ ] Подключена реклама: sticky-баннер и полноэкранная реклама после забега.
- [ ] Есть лидерборд или кнопка входа для него.
- [ ] Мобильное поле занимает весь экран, нет прокрутки и контекстного меню.
- [ ] Десктопное поле примыкает к краю доступной области.
- [ ] Собирается ZIP с `index.html` в корне.
- [ ] `node --test tests/*.test.js` проходит полностью.
- [ ] В консоли браузера нет ошибок и 404 на production-сборке.

### 1.2. Организационная готовность

Эти действия агент не выполняет, но должен подготовить всё необходимое и передать пользователю:

- [ ] Профиль разработчика и договор с Яндексом.
- [ ] Черновик игры в Консоли.
- [ ] Промоматериалы: иконка, обложка, скриншоты, горизонтальное видео.
- [ ] Тексты описания на русском и английском.

## 3. Этап 1. Создать `platform.js`

### 3.1. Файлы

- Новый: `platform.js`.

### 3.2. Действия

Создать браузерный модуль `window.Platform` без зависимостей и без ES-модулей. Он должен:

- инициализировать SDK;
- безопасно работать, если SDK не загрузился;
- вызывать Game Ready;
- размечать геймплей;
- подписываться на паузу и возобновление;
- отдавать язык;
- загружать и сохранять данные игрока;
- показывать полноэкранную рекламу;
- проверять авторизацию;
- открывать диалог входа;
- отправлять результат в лидерборд.

Контракт API:

| Метод | Назначение |
| --- | --- |
| `Platform.init()` | `YaGames.init()`, получение `player`, подписка на события |
| `Platform.onPause(callback)` | Регистрация обработчика `game_api_pause` |
| `Platform.onResume(callback)` | Регистрация обработчика `game_api_resume` |
| `Platform.ready()` | `LoadingAPI.ready()` один раз |
| `Platform.gameplayStart()` | `GameplayAPI.start()` |
| `Platform.gameplayStop()` | `GameplayAPI.stop()` |
| `Platform.lang()` | `ysdk.environment.i18n.lang` с fallback |
| `Platform.load(keys)` | `player.getData(keys)` |
| `Platform.save(data)` | `player.setData(data, true)` |
| `Platform.saveStats(stats)` | `player.setStats(stats)` |
| `Platform.showFullscreenAd()` | Promise с результатом показа |
| `Platform.isAuthorized()` | Проверка авторизации |
| `Platform.auth()` | Осознанный вход через `openAuthDialog()` |
| `Platform.submitScore(name, score)` | `leaderboards.setScore()` |
| `Platform.pausedByPlatform` | Флаг паузы от платформы |

### 3.3. Требования к реализации

- Все вызовы SDK обёрнуты в `try/catch`.
- `init()` возвращает `null`, если `window.YaGames` отсутствует.
- `getPlayer()` вызывается один раз. Не вызывать его на каждый кадр.
- `setData()` и `setStats()` не вызывать на каждом кадре.
- `ready()` идемпотентен: повторный вызов ничего не делает.
- `gameplayStart()` и `gameplayStop()` безопасны при отсутствии SDK.
- `showFullscreenAd()` всегда завершает Promise, даже при ошибке.
- `submitScore()` проверяет `ysdk.isAvailableMethod('leaderboards.setScore')`.
- В консоль не попадают необработанные Promise rejection.

### 3.4. Локальный запуск без SDK

Production `index.html` использует `/sdk.js`. Для локальной проверки:

- запускать игру через статический сервер, а не `file://`;
- при необходимости создать локальную заглушку `sdk.js` в корне, которая определяет `window.YaGames` с минимальным mock;
- заглушку не включать в итоговый ZIP;
- альтернатива — тестировать через debug-панель Консоли.

Если SDK нет, `Platform.init()` возвращает `null`, игра продолжает работать на `localStorage`. Это не отменяет требование вызвать Game Ready в production.

### 3.5. Проверка

```powershell
node --check platform.js
```

Ручная проверка:

- [ ] Игра запускается без SDK и не падает.
- [ ] `Platform` доступен в `window`.
- [ ] Повторный `Platform.ready()` не вызывает ошибку.
- [ ] `Platform.lang()` возвращает `ru` или `en`, а не пустую строку.
- [ ] `Platform.showFullscreenAd()` при отсутствии SDK сразу возвращает `false`.

### 4.3. Создать `i18n.js`

Модуль должен экспортировать `window.I18n` и быть совместимым с Node для тестов.

Контракт:

| Метод | Назначение |
| --- | --- |
| `I18n.normalize(lang)` | Привести `ru-RU`, `en-US` к `ru`, `en` |
| `I18n.t(lang, key, vars)` | Текст по ключу с подстановкой |
| `I18n.cause(lang, code)` | Причина смерти по коду |
| `I18n.notice(lang, event)` | Текст уведомления по событию |
| `I18n.apply(lang, root)` | Обновить `[data-i18n]`, `[data-i18n-aria]`, `[data-i18n-html]` |

Требования:

- `TEXT.ru` и `TEXT.en` имеют одинаковый набор ключей.
- Для отсутствующего ключа возвращается ключ, а не `undefined`.
- `apply()` не использует `innerHTML` для пользовательских данных. Только для статических доверенных строк из словаря.
- Для `aria-label` использовать `data-i18n-aria`, чтобы не ломать доступность.
- Для строк с `<br>` и `<em>` использовать отдельные ключи или `data-i18n-html` с доверенным статическим HTML.

### 4.5. Изменить `engine.js`

Сейчас причины и уведомления — русские строки в `engine.js:86-115`. Нужно перевести их на коды.

Причины:

```text
'Пропущена платформа' -> 'fall'
'Шипы'                -> 'spikes'
'Лазер'               -> 'laser'
'Лазерная мина'       -> 'mine'
```

Заменить вызовы:

- `this.damage('Пропущена платформа')` → `this.damage('fall')`;
- `this.damage('Шипы')` → `this.damage('spikes')`;
- `this.damage('Лазер')` → `this.damage('laser')`;
- `this.damage('Лазерная мина')` → `this.damage('mine')`.

Внутри `damage(cause)` проверку `cause!=='Пропущена платформа'` заменить на `cause!=='fall'`.

Уведомления:

- `emit('notice','УРОВЕНЬ '+level+' · Новый сектор')` → `emit('notice',{key:'levelUp',level})`;
- `emit('notice','Щит поглотил удар')` → `emit('notice',{key:'shield'})`;
- `emit('notice','Резервный модуль · спасение')` → `emit('notice',{key:'rescue'})`;
- `emit('notice','Полёт завершён')` → `emit('notice',{key:'flightEnd'})`.

`emit()` можно оставить прежним: он просто кладёт объект в `events`. Главное — приложение должно читать `e.key`, а не только `e.text`.

Не менять:

- `this.cause` остаётся строкой, но теперь это код;
- порядок событий;
- момент смерти;
- правила щита, резерва и полёта.

### 5.2. Порядок запуска

В конце `app.js` вместо текущего `menu(); requestAnimationFrame(frame);`:

```js
Platform.onPause(() => {
  if (state === 'playing') {
    platformPausedRun = true;
    pause();
  }
});

Platform.onResume(() => {
  if (platformPausedRun && state === 'paused') {
    platformPausedRun = false;
    resume();
  }
});

applyLang(Platform.lang());
menu();
requestAnimationFrame(frame);

Platform.init().then(async () => {
  Platform.ready();

  const cloud = await Platform.load(['best', 'settings']);

  if (cloud?.best > best) {
    best = cloud.best;
    $('best').textContent = String(best).padStart(5, '0');
  }

  if (cloud?.settings) {
    prefs = { ...prefs, ...cloud.settings };
    document.documentElement.style.setProperty('--touch', prefs.touchsize + 'px');
    applyLang(Platform.lang());
    if (state === 'menu') menu();
  }

  if (Platform.lang() !== lang) {
    applyLang(Platform.lang());
    if (state === 'menu') menu();
  }
});
```

Добавить на верхнем уровне `app.js`:

```js
let platformPausedRun = false;
```

`applyLang` и `lang` — из `i18n.js` / `app.js` по выбранной реализации.

### 5.4. Пауза и звук

- `pause()` должен останавливать музыку и звуки.
- При `game_api_pause` игра ставится на паузу, если она была в `playing`.
- При `game_api_resume` игра возобновляется только если пауза была вызвана платформой.
- Ручная пауза игрока не должна сниматься автоматически.
- При рекламе музыка не играет.
- При возврате на вкладку музыка не запускается без действия пользователя.

## 6. Этап 4. Облачные сохранения

### 6.1. Файлы

- `app.js`.
- `platform.js` — уже готовые методы.

### 6.2. Схема данных

```js
{
  best: 1234,
  settings: {
    volume: 35,
    music: 15,
    reduced: false,
    touchsize: 56,
    left: 'KeyA',
    right: 'KeyD',
    jump: 'Space'
  },
  lastRun: {
    seed: 2026,
    version: '1.2.0',
    score: 1234,
    jumps: 80,
    level: 6,
    maxCombo: 12,
    cause: 'laser'
  }
}
```

Правила:

- `localStorage` остаётся кэшем и fallback.
- В облако не отправлять `game.inputs` целиком.
- `lastRun` — краткая сводка, не полный лог.
- `best` сохранять после завершения забега.
- `settings` сохранять с debounce 800 мс.
- `setData` — не чаще 100 раз за 5 минут.
- `setStats` — не чаще 60 раз за 1 минуту.
- `getPlayer` — не чаще 20 раз за 5 минут.

### 6.3. Изменения в `finish()`

```js
const isRecord = game.score > best;
best = Math.max(best, game.score);

Platform.save({
  best,
  settings: prefs,
  lastRun: {
    seed: game.seed,
    version: SpaceJumper.C.version,
    score: game.score,
    jumps: game.jumps,
    level: game.level,
    maxCombo: game.maxCombo,
    cause: game.cause
  }
});

Platform.saveStats({ best });

if (isRecord) {
  Platform.submitScore('spacejumper_best', best);
```

## 9. Этап 7. Мобильная и десктопная компоновка

### 9.1. Файлы

- `index.html` — viewport;
- `style.css` — переопределения;
- `app.js` — запрет контекстного меню и выделения.

### 9.2. Требования

- Мобильное игровое поле занимает весь доступный экран.
- Нет шапки, боковых панелей и футера во время игры на мобильном.
- Нет прокрутки страницы и swipe-to-refresh.
- Нет контекстного меню и выделения на игровом поле.
- Сенсорные кнопки учитывают safe-area.
- На десктопе активное поле примыкает к краю доступной области.
- Пропорции поля не искажаются: 540 × 960.
- При resize и повороте элементы не обрезаются.

### 9.3. CSS

Добавить в конец `style.css` блок переопределений, чтобы не редактировать длинные строки:

```css
html,
body {
  height: 100%;

  overscroll-behavior: none;
}

body {
  touch-action: none;
}

.game-frame,
canvas,

  user-select: none;

  -webkit-touch-callout: none;
}

.game-frame {
  touch-action: none;
}

dialog {
  max-height: 90dvh;
  overflow-y: auto;
  touch-action: auto;
}

@media (max-width: 800px) {
  header,
  .intro,
  .mission,
  footer {
    display: none;
  }

  main {
    display: block;
    max-width: none;
    height: 100dvh;
    margin: 0;
    padding: 0;
  }

  .game-frame {
    width: 100vw;
    height: 100dvh;
    max-height: none;
    border: 0;
    border-radius: 0;
  }

    left: calc(16px + env(safe-area-inset-left));
    right: calc(16px + env(safe-area-inset-right));
  }

```

Для десктопа:

- убрать `max-height: calc(100dvh - 150px)` у `.game-frame`;
- сделать игровое поле основным экраном;
- скрыть или убрать боковые панели, если они не помещаются;
- поле должно занимать высоту или ширину доступной области, а не висеть в центре с большими отступами.

Если сохраняете боковые панели, проверьте требование 1.6.2.1: активное поле должно примыкать к краю доступной области. Проще всего скрыть маркетинговые панели и оставить игру.

### 9.4. Пропорции

Не растягивайте canvas. Если экран не 9:16, используйте letterbox с фоном:

```css

  place-items: center;
  background: #090e1c;
}

  width: auto;
  height: 100%;
  max-width: 100%;
  aspect-ratio: 540 / 960;
}
```

Проверьте, что HUD и оверлей остаются внутри поля.

### 9.5. Viewport

В `index.html`:

```html
<meta name="viewport"
      content="width=device-width,initial-scale=1,maximum-scale=1,user-scalable=no,viewport-fit=cover">
```

`user-scalable=no` ограничивает доступность, но помогает выполнить требования к отсутствию зума и прокрутки. Если хотите сохранить масштабирование, компенсируйте это `touch-action: none` на игровом поле.

### 9.6. Контекстное меню

В `app.js`:

```js
const frame = document.querySelector('.game-frame');

frame.addEventListener('contextmenu', (event) => {
  event.preventDefault();
});

frame.addEventListener('selectstart', (event) => {
  event.preventDefault();
});
```

Не навешивайте запрет на поля ввода и `dialog`, чтобы не сломать настройки.

### 9.7. Полноэкранный режим

Опционально, по первому действию пользователя:

```js
function requestFullscreenOnce() {
  if (document.fullscreenElement) return;
  document.documentElement.requestFullscreen?.().catch(() => {});
}
```

Вызывать из кнопки «Начать забег» на мобильном. Ошибка не должна ломать игру. Если iframe не разрешает Fullscreen API, достаточно визуального полноэкранного поля.

### 9.8. Проверка

- [ ] 360 × 640: поле на весь экран, кнопки не перекрыты.
- [ ] 390 × 844: нет прокрутки.
- [ ] 768 × 1024: элементы не обрезаны.
- [ ] 1366 × 768: поле примыкает к краю, нет больших пустых полей.
- [ ] 1920 × 1080: пропорции сохранены.
- [ ] Долгое нажатие не выделяет текст.

- [ ] Sticky-баннер не перекрывает управление.

## 14. Риски и как их избежать

| Риск | Решение |
| --- | --- |
| `/sdk.js` не загружается локально | Запускать через сервер и локальную заглушку, не включать её в архив |
| Абсолютный URL на S3 в архиве | Использовать только `/sdk.js` |
| Game Ready вызван до меню | Вызывать после появления интерактивного меню |
| Игра возобновляется после ручной паузы | Флаг `platformPausedRun` и проверка состояния |
| Звук играет во время рекламы | Останавливать музыку в `pause()` и при `game_api_pause` |
| Прогресс не сохраняется | Локальный кэш + `setData` + `setStats`, включить облачные сохранения |
| Слишком частые сохранения | Debounce, сохранение только после забега и изменения настроек |
| Локализация ломает тесты | Обновить причины смерти на коды и тесты |
| Потеря ключей перевода | Тест на паритет RU/EN и проверка `data-i18n` |
| Мобильное поле не на весь экран | Скрыть шапку и панели, `100dvh`, safe-area |
| Прокрутка и контекстное меню | `overflow:hidden`, `touch-action:none`, `contextmenu` |
| Портретная игра не проходит 16:9 скриншоты | Делать крупные кропы реального геймплея |
| Реклама мешает игре | Показывать только после завершения забега |
| Лидерборд падает у гостя | Проверять авторизацию и `isAvailableMethod` |
| Архив с вложенной папкой | Проверять `tar -tf`, `index.html` в корне |
