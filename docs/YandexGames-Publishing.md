# Публикация SpaceJumper на Яндекс Играх

Практическая инструкция для текущей версии проекта: что уже готово, что обязательно доработать, как собрать архив, заполнить черновик, пройти модерацию и что делать после публикации.

Дата подготовки: ноябрь 2026 года. Требования Яндекс Игр меняются, поэтому перед отправкой сверяйтесь с актуальными разделами [Консоли разработчика](https://games.yandex.ru/console) и [документации](https://yandex.ru/dev/games/doc/ru/concepts/requirements.md).

---

## 1. Краткий вывод (актуализировано 21.11.2026)

В версии 1.2.0 уже реализованы SDK Яндекс Игр, Game Ready, Gameplay API, пауза/возобновление, RU/EN локализация, облачные сохранения, лидерборд и полноэкранная реклама. Игра использует Canvas 2D, статические локальные файлы и Web Audio. Скрипт `scripts/build.ps1` создаёт архив с `index.html` в корне.

**Это не подтверждает готовность к модерации без проверки в Консоли.** Необходимо выполнить автоматические тесты, проверить ZIP и пройти браузерный плейтест на desktop, Android и iOS. Настроить лидерборд `spacejumper_best`, монетизацию, облачные сохранения и карточку игры. Нужны реальные скриншоты и, если запрашивается Консолью, видео.

Тексты RU/EN, предварительный аудит и редактируемые SVG-иллюстрации находятся в [`publishing/`](../publishing/README.md). Иллюстрации не являются скриншотами игрового процесса.

**Примечание:** разделы ниже содержат исторические примеры реализации и первоначальный план; указания «создайте platform.js», «добавьте SDK» и подобные не следует трактовать как текущее отсутствие этих возможностей. Сверяйтесь с исходниками и актуальными требованиями Яндекса.

## 2. Что уже соответствует требованиям

- Игра полностью клиентская, без серверной части и без сборки.
- Все ресурсы локальные: внешних шрифтов, CDN, картинок и аудиофайлов нет.
- Canvas 2D, а не WebGL, поэтому не требуется предупреждение о WebGL.
- Музыка и звуки синтезируются через Web Audio; системный аудиоплеер не открывается.
- Есть управление с клавиатуры и сенсорные кнопки.
- Клавиши обрабатываются через `event.code` в `app.js:14-16`, поэтому раскладка не влияет на управление.
- Пауза при потере фокуса уже реализована: `window.addEventListener('blur', pause)` и `visibilitychange` в `app.js:17`.
- Музыка останавливается при паузе и завершении забега через `sound()` в `app.js:7`.
- Есть обучение, настройки, пауза, экран результата и локальный рекорд.
- Есть нарастающая сложность и мотивация перепроходить игру, что важно для пункта 2.9.
- Гостевая игра возможна: авторизация не требуется.
- Нет покупок, ссылок на внешние ресурсы и реальных призов.
- Код детерминирован по seed, есть автоматические тесты.

### 2.1. Что нельзя потерять при доработке

- Не добавляйте внешние скрипты, шрифты и картинки: требование 1.7 запрещает абсолютные URL на `games.s3.yandex.net`, а общая политика платформы — внешние ресурсы.
- Не добавляйте ссылки на сайт разработчика, соцсети, другие игры и магазины. Внутренняя ссылка `href="./"` в шапке допустима, но лучше заменить её кнопкой без перехода.
- Не добавляйте стороннюю рекламу, кастомные баннеры и покупки вне SDK.
- Не добавляйте интерактивный ИИ. Процедурная генерация платформ — это алгоритм, а не интерактивный ИИ, поэтому ограничение 1.23 не нарушается. Заранее сгенерированные материалы с помощью ИИ допустимы.
- Не оставляйте в интерфейсе надписи «demo», «в разработке», «trial», «beta»: игра должна выглядеть завершённой.
- Не используйте название со словами «free», «top», «best», «бесплатно» и подобными.
- Все графические, звуковые и текстовые материалы должны принадлежать вам или иметь лицензию на распространение. Музыка в `music.js` оригинальная и процедурная, но сохраните подтверждение авторства. Не используйте чужие спрайты, шрифты и сэмплы.

## 4. Доработка игры

### 4.1. Подключение SDK

В production-архиве, который загружается на сервер Яндекса, используйте относительный путь. Абсолютный URL на S3 в архиве запрещён пунктом 1.7.

В `index.html` перед остальными скриптами:

```html
<script src="/sdk.js"></script>
<script src="engine.js"></script>
<script src="music.js"></script>
<script src="platform.js"></script>
<script src="app.js"></script>
```

Почему так:

- `/sdk.js` — рекомендованный относительный путь для игры, размещённой на сервере Яндекса.
- Скрипт должен быть подключён до вызова `YaGames.init()`.
- Если открыть `index.html` напрямую через `file://`, путь `/sdk.js` не сработает. Для локальной разработки используйте локальный статический сервер и заглушку SDK либо тестируйте через debug-панель Консоли. Заглушку нельзя включать в итоговый архив.
- Для игры на собственном домене используется абсолютный путь, но для SpaceJumper достаточно архива на сервере Яндекса.

### 4.2. Обёртка платформы

Создайте `platform.js` — небольшой слой между игрой и SDK. Он должен не ломать локальный запуск, если SDK недоступен.

```js
(function (global) {
  'use strict';

  let ysdk = null;
  let player = null;
  let readySent = false;
  let pausedByPlatform = false;
  const hooks = { pause: null, resume: null };

  async function init() {
    if (!global.YaGames) return null;

    try {
      ysdk = await global.YaGames.init();

      try {
        player = await ysdk.getPlayer();
      } catch (error) {
        player = null;
      }

      ysdk.on?.('game_api_pause', () => {
        pausedByPlatform = true;
        hooks.pause?.();
      });

      ysdk.on?.('game_api_resume', () => {
        pausedByPlatform = false;
        hooks.resume?.();
      });

      return ysdk;
    } catch (error) {
      console.warn('Yandex Games SDK init failed', error);
      return null;
    }
  }

  function onPause(callback) {
    hooks.pause = callback;
  }

  function onResume(callback) {
    hooks.resume = callback;
  }

  function ready() {
    if (!ysdk || readySent) return;
    readySent = true;
    try {
      ysdk.features?.LoadingAPI?.ready?.();
    } catch (error) {
      console.warn('LoadingAPI.ready failed', error);
    }
  }

  function gameplayStart() {
    try {
      ysdk?.features?.GameplayAPI?.start?.();
    } catch (error) {
      console.warn('GameplayAPI.start failed', error);
    }
  }

  function gameplayStop() {
    try {
      ysdk?.features?.GameplayAPI?.stop?.();
    } catch (error) {
      console.warn('GameplayAPI.stop failed', error);
    }
  }

  function lang() {
    const raw = ysdk?.environment?.i18n?.lang || global.navigator.language || 'ru';
    return String(raw).slice(0, 2).toLowerCase();
  }

  async function load(keys) {
    if (!player) return null;
    try {
      return await player.getData(keys);
    } catch (error) {
      return null;
    }
  }

  async function save(data) {
    if (!player) return false;
    try {
      await player.setData(data, true);
      return true;
    } catch (error) {
      return false;
    }
  }

  async function saveStats(stats) {
    if (!player) return false;
    try {
      await player.setStats(stats);
      return true;
    } catch (error) {
      return false;
    }
  }

  function showFullscreenAd() {
    return new Promise((resolve) => {
      if (!ysdk?.adv?.showFullscreenAdv) {
        resolve(false);
        return;
      }

      let settled = false;
      const finish = (value) => {
        if (settled) return;
        settled = true;
        resolve(value);
      };

      try {
        ysdk.adv.showFullscreenAdv({
          onClose: (wasShown) => finish(Boolean(wasShown)),
          onError: () => finish(false)
        });
      } catch (error) {
        finish(false);
      }
    });
  }

  function isAuthorized() {
    try {
      return Boolean(player?.isAuthorized?.());
    } catch (error) {
      return false;
    }
  }

  async function auth() {
    if (!ysdk || !player || isAuthorized()) return isAuthorized();

    try {
      await ysdk.auth.openAuthDialog();
      player = await ysdk.getPlayer();
      return isAuthorized();
    } catch (error) {
      return false;
    }
  }

  async function submitScore(name, score) {
    if (!ysdk || !isAuthorized()) return false;

    try {
      const available = await ysdk.isAvailableMethod('leaderboards.setScore');
      if (!available) return false;

      await ysdk.leaderboards.setScore(name, Math.max(0, Math.floor(score)));
      return true;
    } catch (error) {
      return false;
    }
  }

  global.Platform = {
    init,
    onPause,
    onResume,
    ready,
    gameplayStart,
    gameplayStop,
    lang,
    load,
    save,
    saveStats,
    showFullscreenAd,
    isAuthorized,
    auth,
    submitScore,
    get pausedByPlatform() {
      return pausedByPlatform;
    }
  };
})(window);
```

Важно:

- Все вызовы SDK обёрнуты в `try/catch`: в консоли не должно быть необработанных ошибок.
- `getPlayer()` вызывается один раз. Не вызывайте его на каждый кадр: лимит — 20 запросов за 5 минут.
- `setData()` имеет лимит 100 запросов за 5 минут, `setStats()` — 60 за минуту. Не сохраняйте данные каждый кадр.
- `showFullscreenAdv()` вызывайте только в логических паузах.

### 4.3. Инициализация и Game Ready

Порядок запуска в `app.js`:

1. Показать меню и интерфейс.
2. Инициализировать SDK.
3. Вызвать `Platform.ready()` после того, как меню готово к взаимодействию.
4. Загрузить облачные данные и обновить рекорд/настройки.
5. Если язык изменился, применить его и при необходимости перестроить меню.

Пример в конце `app.js` вместо текущего `menu(); requestAnimationFrame(frame);`:

```js
Platform.onPause(() => {
  if (state === 'playing') {
    platformPausedRun = true;
    pause();
  }
});

Platform.onResume(() => {
  if (platformPausedRun && state === 'paused') {
    platformPausedRun = false;
    resume();
  }
});

applyLang(Platform.lang());
menu();
requestAnimationFrame(frame);

Platform.init().then(async () => {
  Platform.ready();

  const cloud = await Platform.load(['best', 'settings']);

  if (cloud?.best > best) {
    best = cloud.best;
    $('best').textContent = String(best).padStart(5, '0');
  }

  if (cloud?.settings) {
    prefs = { ...prefs, ...cloud.settings };
    document.documentElement.style.setProperty('--touch', prefs.touchsize + 'px');
    applyLang(Platform.lang());
    if (state === 'menu') menu();
  }

  if (Platform.lang() !== lang) {
    applyLang(Platform.lang());
    if (state === 'menu') menu();
  }
});
```

Где:

- `platformPausedRun` — новый флаг: пауза была вызвана платформой, а не игроком.
- `lang` и `applyLang` — переменная и функция локализации из раздела 4.6.
- `menu()` и `draw()` уже обновляют `#best`, поэтому после загрузки облака достаточно обновить `best`.

`Platform.ready()` нужно вызывать, когда игра уже может принимать ввод. Не вызывайте его до появления меню и не показывайте собственный загрузочный экран после вызова.

### 4.4. Gameplay API и пауза

Добавьте вызовы в существующие функции `app.js`:

| Функция | Что добавить |
| --- | --- |
| `menu()` | `Platform.gameplayStop()` |
| `start(tutorial)` | `Platform.gameplayStart()` |
| `pause()` | `Platform.gameplayStop()` |
| `resume()` | `Platform.gameplayStart()` |
| `finish()` | `Platform.gameplayStop()` |

Текущие функции находятся в `app.js:9-13`. Не вызывайте `start()` после `stop()`, пока игрок реально не начал или не возобновил игру.

События `game_api_pause` и `game_api_resume` платформа присылает при:

- показе и закрытии полноэкранной рекламы;
- открытии и закрытии окна покупок;
- переключении вкладок;
- сворачивании и разворачивании окна.

При `game_api_pause`:

- поставьте игру на паузу;
- остановите музыку и звуки;
- вызовите `GameplayAPI.stop()`.

При `game_api_resume`:

- возобновляйте игру только если она была на паузе именно из-за платформы;
- если игрок сам открыл меню или паузу, не запускайте геймплей автоматически;
- вызовите `GameplayAPI.start()`, только если реально возобновили игру.

Стартовая полноэкранная реклама показывается платформой автоматически. Не вызывайте `showFullscreenAdv()` сразу при загрузке: обрабатывайте стартовую рекламу через `game_api_pause` и `game_api_resume`.

### 4.5. Облачные сохранения

Сейчас игра хранит данные только в `localStorage`:

- `sj-best` — рекорд;
- `sj-settings` — настройки;
- `sj-last-run` — последний забег.

Этого недостаточно для полноценного прогресса на разных устройствах. Схема:

1. Локальный `localStorage` остаётся быстрым кэшем и резервом, если SDK недоступен.
2. При старте загружайте `best` и `settings` через `Platform.load(['best', 'settings'])`.
3. Выбирайте лучший рекорд: `Math.max(localBest, cloudBest)`.
4. Настройки объединяйте: `{ ...defaults, ...localSettings, ...cloudSettings }`.
5. После завершения забега сохраняйте `best`, `settings` и краткую сводку последнего забега.
6. После изменения настроек сохраняйте их с задержкой, чтобы не превысить лимит запросов.

Пример сохранения в `finish()`:

```js
const isRecord = game.score > best;
best = Math.max(best, game.score);

Platform.save({
  best,
  settings: prefs,
  lastRun: {
    seed: game.seed,
    version: SpaceJumper.C.version,
    score: game.score,
    jumps: game.jumps,
    level: game.level
  }
});

Platform.saveStats({ best });

if (isRecord) {
  Platform.submitScore('spacejumper_best', best);
}
```

Не отправляйте в облако весь массив `game.inputs`: он может быть большим, а лимит `setData()` — 200 КБ на игрока. Для облака достаточно seed, версии, счёта и статистики. Полный лог ввода можно оставить только локально и ограничить длину.

Для настроек используйте debounce:

```js
let settingsTimer = 0;

function saveSettingsSoon() {
  clearTimeout(settingsTimer);
  settingsTimer = setTimeout(() => {
    Platform.save({ settings: prefs });
  }, 800);
}
```

Вызовите `saveSettingsSoon()` в существующем обработчике изменения настроек в `app.js:21`.

В черновике включите опцию **Игра использует облачные сохранения**, если используете `setData()` и `setStats()`.

Локальный `localStorage` в архиве на сервере Яндекса оборачивается SDK и работает надёжнее, но облачные сохранения всё равно нужны для переноса прогресса и выполнения требований к прогрессу.

### 4.7. Лидерборд

Лидерборд не обязателен, но сильно помогает удержанию и чаще показывает игру в подборках.

Порядок:

1. В Консоли откройте игру → вкладка **Лидерборды**.
2. Создайте лидерборд:
   - техническое название: `spacejumper_best`;
   - отображаемое название: «Лучший счёт» / «Best score»;
   - тип: `numeric`;
   - сортировка: по убыванию;
   - основной лидерборд: по желанию.
3. В коде вызывайте `Platform.submitScore('spacejumper_best', best)` после нового рекорда.
4. Показывайте лидерборд только авторизованным или предлагайте кнопку входа.

Ограничения:

- `setScore` доступен только авторизованным пользователям;
- не чаще 1 запроса в секунду;
- гостевые результаты в SDK-лидерборд не попадают;
- если нужен рейтинг для всех, его можно сделать отдельно в коде или на своём сервере, но для первого релиза достаточно SDK-лидерборда и локального рекорда.

Кнопка входа должна объяснять пользу:

```js
async function loginForLeaderboard() {
  const ok = await Platform.auth();
  if (ok) {
    await Platform.submitScore('spacejumper_best', best);
  }
}
```

Не открывайте окно авторизации автоматически. Пункт 1.2.1 требует осознанного действия пользователя.

### 4.8. Реклама и монетизация

Пункт 1.12 требует подключённую монетизацию. Для SpaceJumper подходящий минимум:

- sticky-баннер;
- полноэкранная реклама после завершения забега.

#### 4.8.1. Sticky-баннер

1. В Консоли откройте вкладку **Реклама**.
2. Включите sticky-баннер:
   - мобильные, портретная ориентация — внизу или вверху;
   - десктоп — справа.
3. Если не управляете баннером через API, оставьте автоматический показ.
4. Убедитесь, что баннер не перекрывает сенсорные кнопки и HUD. Для портретной игры безопаснее нижнее расположение с отступом `env(safe-area-inset-bottom)`.

Если включаете API для sticky-баннера, вызывайте `ysdk.adv.showBannerAdv()` на экране меню и `ysdk.adv.hideBannerAdv()` при необходимости. Не создавайте собственные баннеры.

#### 4.8.2. Полноэкранная реклама

Показывайте её в логической паузе, например после нажатия «Ещё раз» на экране результата:

```js
let runsSinceAd = 0;

async function again() {
  runsSinceAd += 1;

  if (runsSinceAd >= 2) {
    runsSinceAd = 0;
    await Platform.showFullscreenAd();
  }

  start();
}
```

Замените кнопку «Ещё раз» в `finish()` на `again`. Экран результата — логическая пауза, звук уже остановлен, геймплей завершён.

Не делайте так:

- не вызывайте рекламу по таймеру во время игры;
- не вызывайте её сразу при загрузке (стартовая реклама показывается платформой сама);
- не показывайте рекламу между прыжками;
- не показывайте рекламу поверх активного геймплея без паузы;
- не добавляйте сторонние рекламные блоки.

Перед показом рекламы из паузы обязательно:

- остановите музыку;
- вызовите `Platform.gameplayStop()`;
- после закрытия возобновляйте игру только по действию игрока или через `game_api_resume`, если реклама была инициирована платформой.

#### 4.8.3. Rewarded video

Rewarded video не обязателен. Если добавлять, награда должна быть дополнительным бонусом и не влиять на возможность продолжить игру. Пункт 4.5.2 не рекомендует делать продолжение забега обязательным условием. Безопасные варианты:

- щит на следующий забег;
- временный множитель очков;
- косметический эффект.

Не делайте «продолжить забег только после рекламы»: это может быть воспринято как влияние на возможность продолжить игру.

### 4.9. Мобильная и десктопная компоновка

Сейчас на мобильных шапка занимает 60 px, поле ограничено `max-height: calc(100dvh - 84px)`, а на десктопе вокруг поля остаются боковые панели (`style.css`, медиазапросы). Для модерации это риск: активное поле должно примыкать к краю доступной области, а на мобильных игра должна быть полноэкранной.

Рекомендуемое решение — «game-first»: во время игры на экране только игровое поле, HUD и сенсорные кнопки. Маркетинговые блоки, описание управления и телеметрию можно перенести в меню или на экран паузы.

Добавьте в `style.css`:

Если хотите сохранить боковые панели, они не должны уменьшать активное поле: поле всё равно должно примыкать к краю.

#### 4.9.2. Запрет контекстного меню и выделения

```js
const frame = document.querySelector('.game-frame');

  event.preventDefault();
});

frame.addEventListener('selectstart', (event) => {
  event.preventDefault();
});
```

Не навешивайте запрет на всю страницу: поля ввода в настройках должны оставаться удобными. Для игрового поля достаточно `contextmenu`, `selectstart`, `touch-action: none` и `-webkit-touch-callout: none`.

#### 4.9.3. Прокрутка, зум и поворот

- `overflow: hidden` и `overscroll-behavior: none` убирают прокрутку и swipe-to-refresh.
- `touch-action: none` на игровом поле убирает двойной тап и прокрутку жестами.
- В `viewport` уже есть `viewport-fit=cover`; при необходимости добавьте `maximum-scale=1, user-scalable=no`, но помните, что это ограничивает доступность.
- При повороте экрана прогресс должен сохраняться. Сохраняйте рекорд и настройки сразу после действий.
- В черновике выберите ориентацию **Портретная**. Если выбрать «Любая», придётся делать отдельную альбомную компоновку.

#### 4.9.4. Полноэкранный режим

Требование 1.6.1.1 требует полноэкранного режима на мобильных. В первую очередь это означает, что игровое поле занимает весь доступный экран без шапки и полей. Дополнительно можно вызвать Fullscreen API по первому действию пользователя:

```js
function requestFullscreenOnce() {
  if (document.fullscreenElement) return;
  document.documentElement.requestFullscreen?.().catch(() => {});
}
```

Вызовите функцию из обработчика кнопки «Начать забег» на мобильном устройстве. Если браузер или iframe запрещает полноэкранный режим, ошибка не должна ломать игру. Проверьте поведение в Яндекс Браузере, Chrome на Android и Safari на iOS.

### 4.10. Звук и доступность

- Оставьте отдельные громкости эффектов и музыки: они уже есть в `index.html:7`.
- Добавьте явный переключатель «Звук включён/выключен» — это рекомендуемый пункт 6.2. Ползунок громкости до 0 тоже работает, но переключатель понятнее.
- Убедитесь, что при потере фокуса, паузе и рекламе музыка останавливается. Сейчас `pause()` вызывает `sound()`, который останавливает музыку; дополните это обработкой `game_api_pause`.
- После возврата на вкладку не запускайте музыку автоматически без действия пользователя. AudioContext должен возобновляться по жесту.
- Не делайте цвет единственным сигналом опасности: шипы, лазеры и мины уже имеют форму и предупреждения.
- Проверьте контраст HUD и кнопок на светлом и тёмном фоне.

### 4.11. Что ещё рекомендуется

- Добавьте кнопку «Войти для рейтинга» с пояснением, но не требуйте авторизацию.
- Добавьте отзыв/оценку через SDK, если хотите: `ysdk.feedback` (опционально).
- Добавьте ссылку на политику конфиденциальности текстом, если будете собирать данные. Сейчас игра не собирает персональные данные.
- Добавьте контактный email в профиль разработчика.
- Не добавляйте стороннюю аналитику без необходимости. Метрик Консоли обычно достаточно; официальная интеграция с Яндекс Метрикой описана в документации, но внешние скрипты нужно проверять отдельно.

```powershell
$stage = "build\spacejumper"

Compress-Archive -Path "$stage\*" -DestinationPath "build\spacejumper.zip" -Force

Проверка корня архива:

tar -tf build\spacejumper.zip
```

В выводе `index.html` должен быть без префикса папки. Проверка размера:

(Get-ChildItem $stage -Recurse | Measure-Object Length -Sum).Sum / 1MB

### 8.3. Особенность портретной игры

SpaceJumper — вертикальная игра 540 × 960. Это создаёт две сложности:

1. **Горизонтальные скриншоты 16:9.** Если просто вставить вертикальное поле в широкий кадр, геймплей займёт меньше 70% изображения. Решение: делайте горизонтальные скриншоты как крупный кроп реального игрового поля. Например, снимите кадр 960 × 540 из центра Canvas (или увеличьте Canvas и обрежьте), затем приведите к 1920 × 1080. На скриншоте должны быть видны платформы, персонаж, HUD и опасности. Не добавляйте рамки и большие поля.
2. **Горизонтальное видео 16:9.** Аналогично: не делайте видео с вертикальной игрой в центре и чёрными полосами по бокам — геймплей может не пройти проверку 70%. Записывайте видео с крупным игровым кадром, зумируйте поле, чередуйте планы и оставляйте не менее 70% времени на реальный геймплей.

Вертикальное видео 9:16, наоборот, идеально подходит для этой игры.

### 8.4. Идеи для иконки и обложки

- Тёмный космический фон, холодная подсветка платформ.
- Астронавт в прыжке вверх, за ним след импульсных ботинок.
- Мятный акцент `#bcf782` — фирменный цвет SpaceJumper.
- На обложке — точное название `SpaceJumper`, без мелкого нечитаемого текста.
- Не используйте скриншот интерфейса как иконку или обложку.
- Не добавляйте рамки, скруглённые углы, бейджи Яндекс Игр и статус-бар.
- Для maskable-иконки держите персонажа и стрелку в центральном круге, чтобы маска не обрезала главное.

### 8.5. Сценарий горизонтального видео на 20–28 секунд

1. 0–3 с: меню и название, короткий старт.
2. 3–8 с: обучение, прыжок сквозь платформу и посадка сверху.
3. 8–16 с: обычный забег, сбор кристаллов, серия и рост множителя.
4. 16–23 с: шипы, лазер с предупреждением, ловкий разворот.
5. 23–28 с: экран результата, новый рекорд, кнопка «Ещё раз».

Видео должно быть записано с реального геймплея, без чужих игр, водяных знаков и внешних ссылок.

### 8.6. Как снять материалы

- Запустите игру в Яндекс Браузере или Chrome на десктопе.
- Для мобильных скриншотов используйте реальное мобильное устройство или эмуляцию с корректным viewport 390 × 844 / 360 × 800.
- Включите режим без лишних элементов: для скриншотов лучше временно скрыть шапку и боковые панели, оставив только игровое поле и HUD.
- Для видео используйте запись экрана в 1920 × 1080 или 1280 × 720, 30 или 60 fps.
- Не растягивайте вертикальное поле: лучше кроп, чем искажение пропорций.

## 11. После публикации

- Первую неделю игра находится в разделе «Новые», алгоритмы определяют аудиторию.
- Примерно через две недели появляется рейтинг вовлечения и удержания.
- Если рейтинг держится на уровне 30 или ниже в течение трёх недель, игру могут снять с публикации. Следите за качеством и отзывами.
- Обновления с изменением файлов проходят полную модерацию; изменения только промоматериалов — контентную.
- Новые версии должны сохранять основную концепцию. Нельзя загружать совершенно другую игру как обновление.
- Смотрите метрики в Консоли: удержание, среднюю длительность сессии, конверсию в повторный забег, доход от рекламы.
- A/B-тесты иконок и обложек помогают выбрать лучший креатив, но на время теста нельзя менять эти материалы.
- Отвечайте на отзывы и исправляйте критические ошибки.
- Для роста удержания можно добавить ежедневный маршрут, испытания и косметику, но только после стабильного релиза.

## 14. Итог

SpaceJumper уже близок к публикации: у него правильная статическая архитектура, локальные ресурсы, сенсорное управление и завершённый игровой цикл. Основная работа — не в геймплее, а в интеграции с платформой: SDK, события, сохранения, язык, реклама, компоновка и промоматериалы. Если закрыть блокеры из раздела 12.1 и собрать архив по разделу 5, игра будет готова к модерации.

Главное правило: не отправляйте игру, пока не проверили её в режиме черновика с debug-панелью на десктопе и мобильном. Одно замечание модерации стоит дороже, чем час собственного тестирования.
